# AI 博客网站构建说明

本文档用于指导 AI 在本仓库中构建一个现代、可维护、可扩展，并具有强烈视觉个性的个人博客网站。AI 在执行任务时应优先遵循本文件约定，并结合仓库现有代码风格进行实现。

## 项目目标

构建一个以内容阅读体验为核心，同时具备 3D 像素视觉、黑白灰极客美学和千禧年游戏机风格的个人博客网站，适合发布技术文章、随笔、项目记录和长期知识沉淀。

网站应具备：

- 清晰的信息架构，用户可以快速找到文章、分类、标签和作者信息。
- 舒适的阅读体验，包括合理的字号、行高、段落间距和代码块样式。
- 良好的移动端适配，在手机、平板和桌面端都能自然阅读。
- 易于维护的内容结构，后续可以持续添加文章。
- 良好的性能、SEO 和可访问性基础。
- 明确的像素风与千禧年游戏机风，包括低分辨率质感、游戏 UI 语言、电子设备边框、启动界面和复古交互反馈。
- 借鉴 `careers.kimi.com` 的视觉分析：极致黑白灰、8-bit 像素、CRT 噪点、星空动效、终端感和场景式叙事。

## 推荐技术栈

本项目指定使用以下技术栈：

- 框架：Next.js
- 语言：TypeScript
- 样式：Tailwind CSS
- 内容：Markdown 或 MDX
- 动画：GSAP，用于复杂滚动时间线、场景切换和像素动效；简单动效可使用 CSS。
- 图标：lucide-react
- 代码高亮：Shiki 或 rehype-pretty-code
- 主题：类 kimi 主题
- 部署目标：Vercel

如果仓库已经存在其他技术栈，应尊重现有技术栈，不要为了偏好重写项目。

不要引入现成大型 UI 组件库，例如 Ant Design、MUI、Chakra UI 或 Radix UI。像素面板、按钮、弹窗、卡片和控制台组件应基于 React 组件、Tailwind CSS 和少量原生脚本手写实现。

## 网站结构

至少包含以下页面：

- 首页：第一屏必须是一个巨大的老式显示屏，展示站点定位、最新文章、精选文章和主要分类入口。
- CRT Device Frame / 画中画：首页不应只把 CRT 当作装饰，而应逐步把博客内容放置在 CRT 显示器的屏幕框架内展示，形成“屏幕中的屏幕”的叙事感。文章预览、分类入口、归档指标或终端菜单应优先作为 CRT 屏幕内的界面内容出现。
- 首页场景叙事：可参考招聘官网的单页式滚动体验，将首页拆为启动屏、控制面板、精选文章、归档指标、探索入口和页脚 CTA 等连续场景。
- 文章列表页：按时间倒序展示文章，支持摘要、发布日期、标签和阅读时间。
- 文章详情页：渲染 Markdown/MDX 内容，支持标题、日期、标签、目录、代码块和上一篇/下一篇导航。
- 分类页：展示所有分类，并可进入某个分类下的文章列表。
- 标签页：展示所有标签，并可进入某个标签下的文章列表。
- 关于页：介绍作者、写作主题、联系方式和项目链接。
- 404 页面：提供简洁提示和返回首页入口。

可选增强页面：

- 归档页：按年份和月份聚合文章。
- 项目页：展示个人项目、开源项目或案例。
- 搜索页：支持本地文章搜索。

## 内容模型

文章建议存放在 `content/posts` 或框架约定的等价目录中。

每篇文章应包含 frontmatter：

```yaml
---
title: "文章标题"
description: "文章摘要，用于列表页和 SEO。"
date: "2026-06-19"
updated: "2026-06-19"
category: "技术"
tags:
  - "Next.js"
  - "前端"
draft: false
---
```

内容处理要求：

- `draft: true` 的文章默认不在生产环境展示。
- 自动计算阅读时间。
- 自动生成文章 slug，优先使用文件名。
- 文章摘要优先使用 `description` 字段。
- 日期展示使用统一格式，例如 `2026-06-19`。

## 设计原则

博客应以阅读和内容发现为第一优先级，同时使用像素风、单色极客美学和千禧年游戏机风形成鲜明记忆点。

参考网站主题应用原则：

- 参考对象是 `careers.kimi.com` 的视觉与交互分析，目标是借鉴其设计语言，而不是复刻招聘站内容、品牌资产或具体文案。
- 保留其沉静、冷峻、智性的黑白灰气质，并将“招聘流程”式叙事转化为“博客探索”式叙事。
- 将像素月球、星空、终端、控制面板、指标展示和场景滚动等元素改造为博客语境。

视觉风格：

- 网站应明确追求以「CRT 显示器」为视觉载体的「复古 / 怀旧未来主义」网页设计，而不是只做普通黑色博客模板。CRT 显示器应承担 Device Frame / Mockup 的角色，像手机或笔记本 mockup 一样承载内容、建立焦点，并传递“正在观看一个屏幕中的屏幕”的体验。
- 当前实现若只是首页有 Three.js CRT 模型、屏幕内有少量标题或指标，只能视为“CRT 主视觉雏形”。完整目标是让 CRT 屏幕成为博客探索入口和内容展示容器，例如在屏幕内切换频道、预览最新文章、展示精选文章卡片、显示分类菜单、响应滚动场景变化。
- 主色调必须以纯黑、纯白和不同深浅的灰色为核心，整体接近单色电影、深空终端和极客控制台。
- 可以少量使用终端绿作为 CRT 噪点、状态灯、代码雨或屏幕信号色，但不要形成花哨霓虹多彩风格。
- 界面应有游戏机系统 UI 的气质，但不能牺牲正文可读性。
- 可以使用像素边框、点阵阴影、低分辨率纹理、网格背景和屏幕噪点，但要控制强度。
- 避免普通企业官网式极简风、通用模板风和过度柔和的现代 SaaS 风。
- 页面内容宽度应受控，正文不应铺满超宽屏。
- 文章正文建议最大宽度为 `680px` 到 `760px`。
- 卡片、按钮和输入区域可以模拟游戏机面板、像素窗口或卡带标签，但层级要清晰。
- 颜色系统应包含文本、背景、边框、强调色、警示色、代码块颜色和外框颜色，不要只依赖单一色系。
- 类 kimi 主题建议使用黑色底、白色主文字、灰色边框、暗灰面板、暖白高亮和极少量终端绿。

字体与排版：

- 像素标题、英文标识、数字指标、按钮文字和控制台标签优先使用 `Fusion Pixel 12px Mono zh_hans`。
- 如果无法直接使用该字体，应选择合法可用的等价开源像素字体，并在说明中注明替代原因。
- 长正文使用 `ui-sans-serif, system-ui, sans-serif`，保证中文和英文阅读舒适。
- 不要让像素字体承担大段正文阅读，像素字体主要用于标题、导航、数据和 UI 装饰。

3D 与动效：

- 使用 Three.js 构建真实 3D 场景，不要用纯 CSS 或静态 SVG 假装 3D。
- 首页 3D 场景的主体必须是巨大的老式 CRT 显示屏，不要替换为普通笔记本、手机、抽象几何体或纯背景粒子。
- 显示屏应像一个可运行的博客终端：屏幕内部可以展示站点标题、菜单、最新文章、像素光标、启动文字或滚动信息。
- CRT 屏幕内容应尽量与真实博客内容绑定，而不是硬编码的纯装饰文本。至少应能展示文章数、分类数、标签数、最新文章标题或精选文章摘要；增强版本应支持屏幕频道切换、滚动驱动的屏幕内容变化或点击进入对应页面。
- 设备框架应加强“老式显示器”的物理可信度：厚重外壳、弧面玻璃、屏幕内凹、反光、旋钮、实体按钮、散热孔、接口、贴纸、卡带槽、塑料粗糙度和屏幕辉光都可作为迭代方向。
- 3D 场景应服务于主题，可在显示屏周围加入卡带、像素星球、低多边形桌面、游戏手柄、贴纸或虚拟终端元素，但这些只能作为辅助。
- 可借鉴参考站的像素月球和星空氛围，但应作为背景叙事元素，不要让月球替代巨型老式显示屏成为主角。
- 场景应使用稳定尺寸和响应式约束，避免遮挡正文与导航。
- 3D canvas 在移动端应降级良好，必要时降低模型复杂度、阴影、粒子数量或渲染分辨率。
- GSAP 可用于控制首页场景滚动、CRT 启动、星空穿梭、控制面板切换和文章卡片入场。
- 首页可采用全屏滚动（Fullpage Scroll）实现“滚一下切一屏”的场景体验。可以使用原生 CSS scroll snap、GSAP ScrollTrigger，或在确有必要时选择轻量全屏滚动库；不要为了单一滚动效果引入过重依赖。
- 滚动驱动动画（Scroll-driven / triggered animation）应服务于叙事：用户滚动时可以触发 CRT 开机、屏幕频道切换、文章卡片进入屏幕、归档指标变化、星空/噪点运动或设备视角轻微变化。
- 若使用全屏滚动库（Fullpage Scroll Library），例如 `fullPage.js`、`Scrollify` 等，必须评估包体积、可访问性、移动端手势、键盘导航和与 Next.js App Router 的兼容性。优先选择原生 scroll snap 或 GSAP 方案。
- CRT 屏幕效果（CRT Screen Effect）可由扫描线（Scanlines）、磷光发光（Phosphor Glow）、屏幕曲率（Screen Curvature）、色差 / RGB 分离（Chromatic Aberration / RGB Split）、低强度噪点和轻微 flicker 叠加而成。
- 像素化或故障效果库（Pixelation / Glitch Effect Library，例如 `glitchGL`）只能在明确需要且收益明显时引入；优先使用 CSS、Canvas 或 Three.js shader 实现轻量效果。
- 动效应轻量、有节制，默认不应造成阅读干扰。
- 尊重 `prefers-reduced-motion`，在用户偏好减少动画时降低或关闭旋转、漂浮和粒子动画。

阅读体验：

- 正文字号建议为 `16px` 到 `18px`。
- 正文行高建议为 `1.7` 到 `1.9`。
- 标题层级应清晰，不要在普通内容区域使用过大的 hero 字号。
- 代码块应支持横向滚动、语言标识和语法高亮。
- 图片应具有稳定尺寸或响应式约束，避免加载时页面明显跳动。

交互体验：

- 导航应在桌面和移动端都清晰可用。
- 移动端导航可以使用抽屉菜单或紧凑菜单。
- 标签、分类、返回顶部、复制代码等交互应有明确 hover/focus 状态。
- 交互反馈可以模拟游戏机按钮、菜单选中态、像素光标或启动屏幕，但必须清楚可用。
- 所有可点击元素都应有可访问的名称。

## 功能要求

基础功能：

- 响应式布局。
- 文章列表与文章详情。
- 分类和标签聚合。
- SEO 元信息，包括标题、描述、Open Graph 基础字段。
- RSS feed。
- sitemap。
- 代码高亮。
- 图片优化。
- 深色模式，除非用户明确不需要。
- 类 kimi 主题配置，包括颜色、字体、按钮、卡片、代码块和外框视觉参数。

推荐增强：

- 文章目录。
- 代码块复制按钮。
- 本地搜索。
- 阅读进度条。
- 上一篇/下一篇文章导航。
- 按年份归档。
- 像素风页面转场。
- CRT 画中画内容系统：将最新文章、精选文章、分类菜单和归档指标作为 CRT 屏幕内 UI 展示，而不是全部放在屏幕外的普通页面区块。
- Device Frame 叙事：滚动或交互时让用户感觉是在操作一台博客终端，例如开机、切换频道、进入文章预览、返回目录、显示系统状态。
- 低强度 CRT 扫描线或像素噪点效果。
- 单页式首页场景滚动。
- 全屏滚动（Fullpage Scroll）体验：把首页拆成可逐屏浏览的场景，每一屏都有明确主题，例如启动、CRT 控制台、精选文章、归档指标、探索入口。
- 滚动驱动动画：滚动进度应能驱动 CRT 屏幕内容、屏幕辉光、噪点强度、星空背景或文章卡片状态变化。
- CRT 屏幕效果细化：逐步补齐扫描线、磷光发光、屏幕曲率、RGB 分离、信号干扰和短暂故障动画。
- 类终端代码雨、星空穿梭或像素雪花动效。
- 指标式归档模块，例如文章数、标签数、写作年份、项目数等大号像素数字。

## Vercel 部署要求

本项目部署目标固定为 Vercel。

Next.js 配置要求：

- 优先使用 Vercel 对 Next.js 的原生支持，不要为了部署而强制配置 `output: "export"`。
- 可以使用 App Router、静态生成、动态元数据、Route Handler 和 Vercel 支持的服务端能力，但博客核心页面应尽量静态生成以获得更好的性能。
- `next/image` 可以使用 Next.js 默认图片优化能力；远程图片域名需要在 `next.config.ts` 或 `next.config.mjs` 中显式配置。
- 静态资源应放在 `public/` 下，例如图片、字体和 Open Graph 资源。
- 不需要为 Vercel 配置 GitHub Pages 专用的 `basePath`。
- 如果使用环境变量，应在 Vercel Project Settings 中配置，并在文档中说明变量用途。

部署流程要求：

- 将 GitHub 仓库连接到 Vercel，由 Vercel 自动执行构建和部署。
- 构建命令应使用项目实际包管理器，例如 `npm run build`。
- Vercel 会识别 Next.js 项目并处理输出目录，通常不需要手动指定发布目录。
- 每个 Pull Request 或分支应可生成 Preview Deployment，方便验证 3D 场景和页面布局。
- RSS、sitemap、Open Graph 图片、Three.js 模型和纹理资源都必须在 Vercel 生产环境上可访问。
- 如果使用自定义域名，应在 Vercel Domains 中配置，并确保 canonical URL、Open Graph URL、RSS 和 sitemap 使用生产域名。

## 开发步骤

AI 执行构建时应按以下顺序推进：

1. 检查仓库现状，识别已有框架、包管理器、样式方案和目录结构。
2. 如果项目尚未初始化，使用 Next.js 创建博客项目脚手架，并选择稳定、主流的依赖。
3. 安装并配置 Tailwind CSS、Markdown/MDX、代码高亮和 RSS/sitemap 相关能力。
4. 配置 GSAP，用于首页场景滚动和复杂时间线动效；若未使用复杂滚动，可保持依赖克制。
5. 建立全局布局、导航、页脚、类 kimi 主题色、黑白灰像素 UI 组件和排版基础。
6. 接入或配置像素字体，优先使用 `Fusion Pixel 12px Mono zh_hans`，并设置系统无衬线正文字体。
8. 实现首页场景式滚动，包括启动屏、控制面板、精选文章、归档指标和页脚入口。
9. 实现文章内容读取、frontmatter 解析、slug 生成、排序和过滤。
10. 实现首页、文章列表页和文章详情页。
11. 实现分类页、标签页、关于页和 404 页面。
12. 增加 SEO、sitemap、RSS、Open Graph 和基础可访问性支持。
13. 添加示例文章，覆盖标题、段落、列表、引用、代码块、图片和表格。
14. 配置 Vercel 部署，包括 Next.js 构建配置、必要的环境变量、自定义域名说明和 Preview Deployment 验证流程。
15. 在桌面和移动端验证布局，修复溢出、重叠、跳动和不可点击问题。

17. 运行格式化、类型检查、lint 和构建命令。

## AI 协作规则

AI 在本项目中工作时应遵循：

- 先阅读现有文件，再决定实现方式。
- 优先沿用仓库已有技术栈和代码风格。
- 对新项目默认使用 Next.js，不要改用 Astro、Nuxt、VuePress 或其他博客框架。
- 主题描述和视觉系统默认使用“类 kimi 主题”。
- 视觉参考来自 `careers.kimi.com` 的分析，但不要复制其招聘内容、页面截图、品牌素材或原文。
- UI 组件应为项目定制，不要引入大型现成组件库削弱像素主题。
- 不要引入不必要的大型依赖。
- 不要一次性做无关重构。
- 文件命名、组件拆分和样式方案应保持一致。
- 新增功能时同步考虑移动端、可访问性和 SEO。
- 修改完成后应说明改动范围和验证结果。
- 如果无法运行某项验证，应明确说明原因。

## 验收标准

完成后的博客网站应满足：

- 首页、文章列表、文章详情、分类、标签、关于页都可以正常访问。
- 至少包含 3 篇示例文章。
- 页面在移动端和桌面端没有明显布局错乱。
- CRT 不应只是孤立装饰。CRT 作为 Device Frame / Mockup 承载真实博客内容，形成画中画和屏幕中的屏幕叙事。
- 视觉风格明确体现黑白灰、像素风、CRT 终端感和千禧年游戏机风，而不是普通模板风。
- 类 kimi 主题在配色、组件和排版中保持一致。
- 像素标题、数字和 UI 标签使用像素字体，长正文使用高可读性系统字体。
- 首页具有场景式探索体验，而不只是普通文章列表堆叠。
- 正文阅读体验舒适，代码块和图片显示正常。
- `npm run build` 或项目等价构建命令可以通过。
- Vercel 部署配置正确，生产环境和 Preview Deployment 都能正常访问。
- 字体、RSS、sitemap 和 Open Graph 资源在 Vercel 生产环境中路径正确。
- SEO 基础信息存在且每篇文章有独立标题和描述。
- 站点结构便于后续添加新文章。

## 禁止事项

AI 不应：

- 在未确认的情况下删除用户已有内容。
- 为了实现简单博客引入复杂 CMS、数据库或认证系统。
- 使用大量无意义装饰影响阅读。
- 将首页主视觉替换为非老式显示屏主题，例如普通卡片墙、抽象球体、通用粒子背景或普通设备 mockup。
- 直接复制参考网站的招聘文案、截图、品牌资产或完整页面结构。
- 使用鲜艳多彩的霓虹赛博朋克配色覆盖黑白灰主题。
- 用像素字体排大段正文，导致文章难以阅读。
- 只构建营销落地页而不实现真实博客功能。
- 忽略移动端布局。
- 忽略构建错误、类型错误或明显的控制台错误。
